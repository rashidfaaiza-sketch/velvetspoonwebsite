# Deployment and operations

Deploy as a **single Node 24 process on a VM/container with persistent local disk**, behind an HTTPS reverse proxy (Caddy/Nginx or equivalent). This SQLite implementation is not designed for multiple replicas, shared network filesystems, or ephemeral serverless runtimes. Use a managed PostgreSQL adaptation before scaling horizontally.

1. Check out this repository, run `npm ci` and `npm run build` in the release directory. CI can run `npm test`; execute browser checks against a running demo instance.
2. Put `DATA_DIR` on a private persistent volume (for example `/var/lib/velvet-spoon`). Run as an unprivileged dedicated OS user that exclusively owns this directory. Set directory mode 700; keep `.env` and secrets mode 600 outside web roots. Never add this volume or `.env` to a public image, repository or static hosting bucket.
3. Supply environment variables from `.env.example` through your host's secret manager. Set `NODE_ENV=production`, `HOST=127.0.0.1`, `PORT=3000`, exact `APP_ORIGIN=https://YOUR-DOMAIN`, and a random `SESSION_SECRET` of at least 32 characters. If reverse proxy is in another container, bind only to the private container interface/network as required; do not expose the Node port publicly. Configure your own administrator password hash locally using `node scripts/configure-admin.js` and transfer the hash securely. The generated `.env` must never be committed.
4. Start using `npm start` under a process supervisor (systemd or the hosting platform). Configure restart on failure. Terminate TLS at the proxy, forward only to the application, enforce request/upload size limits, and use an exact trusted hostname. Keep cookies secure by using HTTPS `APP_ORIGIN`. Do not cache `/api/*`; do not log request bodies, cookies, token headers or private links.
5. Health check: `GET /api/health` returns `{ok:true,mode:"demo"}` (or your selected mode). Check `/`, `/menu`, `/product/tres-leches`, `/custom-cake`, `/admin`, and policy pages. A health check does not establish real payment readiness.
6. Restrict server outbound access to `api.razorpay.com` and the chosen SMTP host; browsers need `checkout.razorpay.com` and Razorpay's account-enabled checkout assets. If managed-cloud networking blocks those destinations, add the required exact hosts through environment settings; do not disable TLS or bypass the proxy. Dependencies use `registry.npmjs.org`. No remote image/font CDN is required by the storefront.
7. Configure the HTTPS Razorpay webhook and validate its signature/capture handling with test keys before switching to live (README checklist). Razorpay secrets and SMTP values must never be `VITE_*` variables. Configure SMTP with TLS (587 STARTTLS or 465 implicit TLS); preserve certificate verification. Use a verified sender.
8. Back up SQLite consistently using the SQLite backup API or `.backup` while running, or stop the application and copy the entire data directory, including any WAL/SHM files. Also back up media, private references and application key. Encrypt backups and restrict access. Test restoration before launch. Restore the same `SESSION_SECRET`/application key or old private order links will cease working. Raw enquiry token hashes cannot be reversed; customers must retain their private links.
9. Define retention and deletion with the business. This app includes no automated retention schedule, customer deletion portal, automated refunds, or full audit-log UI. Protect customer data through OS permissions, administrator access, backup controls and your approved privacy workflow. Review records flagged `needsReview`, failed outbox entries and unknown payment creation attempts.
10. Reset demo/test data by pointing production at a **new, empty persistent directory**, then approve products/settings again. Preserve any old data securely according to policy; never casually delete a real orders database. Do not reuse test payment attempts under live credentials.

The prepared local preview is not an Internet deployment. Review desktop/mobile screenshots and functionality before publishing or opening live checkout.
